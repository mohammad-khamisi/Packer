# Kubernetes on VMware vSphere with Terraform and Ansible

**English** | [فارسی](README.fa.md)

- **Terraform** (`terraform/`) clones **master** and **worker** VMs from a vSphere template, gives them a static IP and hostname, and writes the Ansible inventory.
- **Ansible** (`ansible/`) prepares the nodes (containerd, kubeadm/kubelet/kubectl, swap, sysctl, firewall, SELinux), bootstraps the cluster with `kubeadm`, installs Calico and joins the workers.
  With more than one master, **kube-vip** floats a virtual IP for the API server between them (HA).

```text
vmware-vsphere/
├── terraform/
│   ├── versions.tf               # providers (vsphere, local)
│   ├── variables.tf
│   ├── main.tf                   # VMs, folder, DRS anti-affinity, inventory generation
│   ├── outputs.tf
│   ├── terraform.tfvars.example  # ⭐ copy and edit
│   └── templates/hosts.ini.tftpl
└── ansible/
    ├── ansible.cfg
    ├── requirements.yml          # ansible.posix, community.general
    ├── inventory/hosts.ini       # generated by Terraform (sample: hosts.ini.example)
    ├── group_vars/all.yml        # ⭐ Kubernetes version, pod CIDR, VIP, Calico, firewall
    ├── site.yml                  # full cluster build
    ├── reset.yml                 # wipe Kubernetes from the nodes
    └── roles/{common,containerd,kubernetes,control_plane,cni,worker}
```

## 1. Prerequisites

- Terraform ≥ 1.5 and Ansible ≥ 2.16 (`pip install ansible`) on a machine that can reach vCenter and the node network.
- A vSphere VM template: Rocky/Alma/RHEL 9–10 or Ubuntu 22.04/24.04 with **open-vm-tools** and **cloud-init** (e.g. one built with the Packer config in this repo; run `cloud-init clean` before templating).
- An SSH key pair (`ssh-keygen -t ed25519`).
- Internet access from the nodes (Docker repo, pkgs.k8s.io, registry.k8s.io, ghcr.io, quay.io).

`customization_method`:
- `cloud-init` (default) – hostname, static IP and the SSH user + key are passed through VMware `guestinfo`.
- `vmware` – classic vSphere guest customization (hostname/IP only; the SSH user and key must already be in the template).

## 2. Create the VMs

```bash
cd vmware-vsphere/terraform
cp terraform.tfvars.example terraform.tfvars && vi terraform.tfvars
export TF_VAR_vsphere_password='...'
terraform init && terraform plan && terraform apply
```

Nodes are defined in the `masters` / `workers` maps (hardware from `master_defaults` / `worker_defaults`, overridable per node). Use 3 masters for HA. `enable_anti_affinity` creates DRS rules to spread nodes across ESXi hosts. `ansible/inventory/hosts.ini` is written automatically.

## 3. Install Kubernetes

```bash
cd ../ansible
vi group_vars/all.yml            # set control_plane_vip when you have more than one master
ansible-galaxy collection install -r requirements.yml   # only needed with plain ansible-core
ansible all -m ping
ansible-playbook site.yml
```

Order: prepare all nodes → `kubeadm init` on the first master → join the other masters one at a time → Calico → join workers → wait until every node is Ready.
The playbook is idempotent; to add nodes, add them in Terraform, `terraform apply`, then re-run `site.yml`.

## 4. Use the cluster

```bash
export KUBECONFIG=$PWD/artifacts/admin.conf
kubectl get nodes -o wide
```

## 5. Tear down

```bash
ansible-playbook reset.yml -e confirm_reset=yes   # remove Kubernetes, keep the VMs
cd ../terraform && terraform destroy              # delete the VMs
```

## Troubleshooting

- **VIP unreachable** – kube-vip uses ARP; the VIP must be a free IP in the node subnet, and the port group must not reject *MAC Address Changes* / *Forged Transmits*.
- **VM has no IP** – check cloud-init in the template and `/var/log/cloud-init.log`.
- **Terraform waits for IP forever** – open-vm-tools must be installed and running in the template.
- **Rocky/RHEL 10** needs an x86-64-v3 CPU (EVC mode Haswell or newer).
- Install the **vSphere CSI driver** afterwards to use vSphere storage for PersistentVolumes.
